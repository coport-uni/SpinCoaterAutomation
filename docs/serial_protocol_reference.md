# 시리얼 통신 규격 레퍼런스

대상 장비: Laurell WS-650MZ-23NPP/LITE, 650 Series Controller, 보드 P/N 15000018 REV. C
작성일: 2026년 9월 14일
용도: 프로토콜 역공학 및 자동화 개발 시 참조할 표준 규격과 판정 기준 모음

이 문서는 장비 고유 조사 결과를 담은 인수인계 문서와 별개입니다. 여기에는 장비와 무관하게 성립하는 공개 규격, 표준값, 판정 기준만 정리합니다.

## 1. RS-232 전기 규격

TIA-232-F 기준입니다.

| 항목 | 송신기 출력 | 수신기 입력 |
|---|---|---|
| 논리 1, mark | 마이너스 5 V에서 마이너스 15 V | 마이너스 3 V보다 음 |
| 논리 0, space | 플러스 5 V에서 플러스 15 V | 플러스 3 V보다 양 |
| 미정의 구간 | 해당 없음 | 마이너스 3 V에서 플러스 3 V |
| 입력 임피던스 | 해당 없음 | 3 kΩ에서 7 kΩ |
| 최대 입력 | 해당 없음 | 플러스마이너스 30 V |
| 개방 회로 출력 | 플러스마이너스 25 V 이하 | 해당 없음 |
| 단락 전류 | 500 mA 이하 | 해당 없음 |

핵심 판정 규칙 두 가지입니다.

첫째, RS-232 송신선은 유휴 상태에서 반드시 음전압입니다. 데이터를 보내지 않는 동안 mark를 유지하기 때문입니다. 접지 기준으로 양전압만 측정된다면 그 핀은 데이터 송신선이 아닙니다.

둘째, RS-232 수신 입력은 접지 방향으로 3 kΩ에서 7 kΩ의 종단 저항을 가집니다. 이 값은 규격 요구사항이며 TTL 입력이나 I2C 버스에서는 나오지 않습니다. 전원을 끈 상태에서 측정할 수 있으므로 가장 안전하고 결정적인 판별법입니다.

### 1.1 TIA-562 저전압 변형

단일 3.3 V 또는 5 V 전원에서 동작하는 최신 트랜시버는 TIA-562를 따르는 경우가 있습니다. 이 경우 스윙이 작아집니다.

| 규격 | 최소 출력 스윙 | 수신 임계 |
|---|---|---|
| TIA-232-F | 플러스마이너스 5 V | 플러스마이너스 3 V |
| TIA-562 | 플러스마이너스 3.7 V | 플러스마이너스 0.3 V |

본 장비의 U18은 SP3232EE이며 데이터시트 전형값이 플러스마이너스 5.4 V입니다. 따라서 유휴 시 송신 핀에서 마이너스 5.0 V에서 마이너스 5.4 V가 측정되는 것이 정상입니다. 이는 고장이 아니라 설계값입니다.

## 2. UART 프레이밍 규격

RS-232는 전기 규격만 정의하며, 비트 배열은 비동기 UART 규약을 따릅니다.

| 구간 | 길이 | 레벨 | 비고 |
|---|---|---|---|
| 유휴 | 가변 | mark | 데이터 없음 |
| 시작 비트 | 1비트 | space | 하강 에지가 프레임 시작 |
| 데이터 비트 | 5에서 9비트, 통상 8 | 데이터 | LSB 우선 전송 |
| 패리티 비트 | 0 또는 1비트 | 계산값 | 없음, 짝수, 홀수, mark, space |
| 정지 비트 | 1, 1.5, 2비트 | mark | 통상 1 |

한 바이트 전송에 소요되는 비트 수입니다.

| 형식 | 총 비트 | 1바이트 전송 시간, 9600 기준 |
|---|---|---|
| 8N1 | 10 | 1.042 ms |
| 8E1 또는 8O1 | 11 | 1.146 ms |
| 7E1 | 10 | 1.042 ms |
| 8N2 | 11 | 1.146 ms |

프레임 해석 시 유의점입니다. 로직 애널라이저에서 시작 비트를 놓치면 전체 바이트가 밀려 해석되므로, 긴 유휴 구간 직후의 첫 하강 에지를 기준점으로 삼아야 합니다.

### 3.2 보율 생성용 클럭

UART 전용 주파수를 쓰는 설계는 표준 보율에서 오차가 0에 수렴합니다. 기판에서 아래 값의 오실레이터나 크리스털이 확인되면 비표준 보율일 가능성은 사실상 없습니다.

| 주파수 | 공약수 | 특징 |
|---|---|---|
| 1.8432 MHz | 1.2288 MHz 계열 | 저속 전용 |
| 2.4576 MHz | 동일 계열 | 저속 전용 |
| 3.6864 MHz | 1.2288 MHz | 115200까지 오차 0 |
| 7.3728 MHz | 1.2288 MHz | 3.6864의 2배 |
| 11.0592 MHz | 1.2288 MHz | 8051 계열에서 흔함 |
| 14.7456 MHz | 1.2288 MHz | 3.6864의 4배 |
| 18.432 MHz | 1.2288 MHz | 중속 이상 |
| 19.6608 MHz | 1.2288 MHz | 3.6864와 공약수 공유 |

확인 필요 항목입니다. 제공된 기판 사진의 하단 영역에서 SG531P 계열 오실레이터로 보이는 부품의 각인이 19.6608M으로 읽힙니다. 실물에서 각인을 확인해 주십시오. 확정되면 보율 후보를 표준 5종으로 안전하게 좁힐 수 있습니다.

### 3.3 16배 오버샘플링 분주비

클럭이 19.6608 MHz이고 UART가 16배 오버샘플링을 쓴다고 가정했을 때의 분주비입니다.

| 보율 | 분주비 | 오차 |

| 9600 | 128 | 0 퍼센트 |
| 19200 | 64 | 0 퍼센트 |
| 38400 | 32 | 0 퍼센트 |
| 57600 | 21.33 | 정수 반올림 시 0.16 퍼센트 |
| 115200 | 10.67 | 정수 반올림 시 0.16 퍼센트 |

## 4. 모듈러 커넥터 규격

### 4.1 포지션 및 접점 표기

| 표기 | 포지션 | 접점 | 통칭 | 폭 |
|---|---|---|---|---|
| 4P4C | 4 | 4 | 핸드셋 커넥터 | 약 7.4 mm |
| 6P2C | 6 | 2 | RJ11 최소 구성 | 약 9.65 mm |
| 6P4C | 6 | 4 | RJ11, RJ14 | 약 9.65 mm |
| 6P6C | 6 | 6 | RJ25 | 약 9.65 mm |
| 8P8C | 8 | 8 | 통칭 RJ45 | 약 11.7 mm |

### 4.2 핀 번호 방향

커넥터를 손에 들고 래치 탭이 아래로, 케이블 삽입구가 자기 쪽을 향하게 놓았을 때 왼쪽에서 오른쪽으로 1번부터 증가합니다. 잭을 보는 방향과 플러그를 보는 방향은 좌우가 뒤집히므로 기준을 먼저 고정해야 합니다.

### 4.3 USOC 색상 코드

| 핀 | 구형 단색 코드 | 현행 페어 코드 | Cat 5e 및 Cat 6 | 페어 | Tip 또는 Ring |
|---|---|---|---|---|---|
| 1 | orange | white/green | white/green | 3 | T |
| 2 | black | white/orange | white/orange | 2 | T |
| 3 | red | blue/white | blue | 1 | R |
| 4 | green | white/blue | white/blue | 1 | T |
| 5 | yellow | orange/white | orange | 2 | R |
| 6 | blue | green/white | green | 3 | R |

1번 페어와 2번 페어의 구형 단색 코드는 확립되어 있으나 3번 페어는 벤더별로 충돌하는 관행이 존재합니다. 즉 red, green, yellow, black 네 색은 신뢰도가 높고 1번과 6번 핀의 색은 신뢰할 수 없습니다.

주의할 점은 이 색상이 신호 기능이 아니라 회선 페어를 가리킨다는 것입니다. 색상으로 TXD와 RXD를 판단해서는 안 되며, 반드시 트랜시버 IC 핀까지 도통 시험으로 확정해야 합니다.

### 4.4 모듈러 커넥터 위 RS-232 표준

6포지션에는 RS-232 표준 배치가 존재하지 않습니다. 8포지션에만 두 가지 관행이 있습니다.

| 규격 | 커넥터 | 핀 1에서 8 |
|---|---|---|
| EIA/TIA-561 | 8P8C | DSR 또는 RI, DCD, DTR, SGND, RX, TX, CTS, RTS |
| Cisco 및 Yost | 8P8C | CTS, DCD, RX, SGND, SGND, TX, DTR, RTS |

6포지션 직렬 통신 사례로는 DEC의 MMJ가 있으나, 래치가 중심에서 벗어난 별도 커넥터이며 전기 규격도 RS-422입니다. 핀 배치는 1번 DTR, 2번 Tx 플러스, 3번 Tx 마이너스, 4번 Rx 마이너스, 5번 Rx 플러스, 6번 DSR입니다. 본 장비의 커넥터는 표준 래치이므로 MMJ가 아닙니다.

## 6. 산업용 시리얼 프로토콜의 전형적 구조

명령어 세트가 비공개인 장비를 역공학할 때 우선 대조할 구조 유형입니다.

| 유형 | 프레임 형태 | 식별 특징 |
|---|---|---|
| ASCII 라인 지향 | 명령 문자열 + CR 또는 CRLF | 인쇄 가능 문자 비율이 높고 0x0D 또는 0x0A가 주기적으로 등장 |
| ASCII 델리미터 | STX + 본문 + ETX + 체크섬 | 0x02로 시작하고 0x03으로 끝남 |
| 이진 고정 길이 | 헤더 + 고정 페이로드 + 체크섬 | 프레임 길이가 항상 동일 |
| 이진 가변 길이 | 헤더 + 길이 필드 + 페이로드 + 체크섬 | 특정 오프셋 값과 실제 길이가 상관 |
| Modbus RTU 유사 | 주소 + 기능코드 + 데이터 + CRC-16 | 프레임 간 3.5 문자 시간 이상의 무음 구간 |

Spin 3000이 Model Number와 Serial Number를 문자열로 비교하고, 설정 항목이 Controller Serial Number나 Inputs/Outputs How Many 같은 계층 구조로 존재한다는 릴리스 노트 정황을 고려하면, ASCII 라인 지향 또는 ASCII 델리미터 계열일 가능성이 우선순위가 높습니다.

## 8. 체크섬 및 CRC 후보

말미 1바이트에서 4바이트를 대상으로 아래 순서대로 검증합니다.

| 알고리즘 | 폭 | 다항식 | 초기값 | 반사 | 최종 XOR |
|---|---|---|---|---|---|
| XOR-8 | 8 | 해당 없음 | 0x00 | 해당 없음 | 해당 없음 |
| Sum-8 | 8 | 해당 없음 | 0x00 | 해당 없음 | 해당 없음 |
| Two's complement sum-8 | 8 | 해당 없음 | 0x00 | 해당 없음 | 해당 없음 |
| LRC | 8 | 해당 없음 | 0x00 | 해당 없음 | 2의 보수 |
| CRC-8 | 8 | 0x07 | 0x00 | 아니오 | 0x00 |
| CRC-8/MAXIM | 8 | 0x31 | 0x00 | 예 | 0x00 |
| CRC-16/MODBUS | 16 | 0x8005 | 0xFFFF | 예 | 0x0000 |
| CRC-16/CCITT-FALSE | 16 | 0x1021 | 0xFFFF | 아니오 | 0x0000 |
| CRC-16/XMODEM | 16 | 0x1021 | 0x0000 | 아니오 | 0x0000 |
| CRC-16/KERMIT | 16 | 0x1021 | 0x0000 | 예 | 0x0000 |
| CRC-32 | 32 | 0x04C11DB7 | 0xFFFFFFFF | 예 | 0xFFFFFFFF |

ASCII 프로토콜인 경우 체크섬이 16진 문자 2자리나 4자리로 인코딩되어 있을 수 있습니다. 예를 들어 실제 값 0x3A가 문자열 `3A`로 실려 2바이트를 차지합니다. 이 경우 원시 바이트 검증이 실패하므로, 말미 2자리와 4자리를 16진 문자열로 해석한 값도 함께 시도해야 합니다.

검증 범위 후보도 모두 시도합니다.

| 범위 후보 | 설명 |
|---|---|
| 전체 프레임에서 체크섬 제외 | 가장 흔함 |
| STX 다음부터 ETX 이전까지 | 델리미터 제외 |
| STX 다음부터 ETX 포함까지 | 델리미터 일부 포함 |
| 길이 필드 이후부터 | 헤더 제외 |

## 9. 타이밍 규칙

| 항목 | 기준 | 용도 |
|---|---|---|
| 문자 시간 | 1비트 폭 곱하기 프레임 비트 수 | 프레임 간격 판정의 단위 |
| 프레임 경계 무음 | 3.5 문자 시간 이상 | Modbus RTU 계열 판정 |
| 응답 대기 상한 | 통상 100 ms에서 1 s | 타임아웃 설계 |
| 주기적 상태 메시지 간격 | 실측 필요 | 650 컨트롤러는 주기 송출을 수행함 |

캡처 데이터에서 바이트 간 간격 히스토그램을 그리면 프레임 경계가 시각적으로 드러납니다. 문자 시간의 1배 부근에 몰린 군집이 프레임 내부이고, 수십 배 이상 떨어진 군집이 프레임 경계입니다.

| 패리티 | `parity` | `serial.PARITY_NONE`, `PARITY_EVEN`, `PARITY_ODD` |
| 정지 비트 | `stopbits` | `serial.STOPBITS_ONE` |
| 읽기 타임아웃 | `timeout` | `0.1` |
| 쓰기 타임아웃 | `write_timeout` | `1.0` |
| 하드웨어 흐름 제어 | `rtscts` | `False` |
| 소프트웨어 흐름 제어 | `xonxoff` | `False` |
| DTR 초기 상태 | `dsrdtr` | `False` |

송신 방지가 필요한 기간에는 포트를 열되 `write` 호출 경로 자체를 코드 수준에서 차단하는 편이 안전합니다. 일부 드라이버는 포트 개방 시 DTR과 RTS를 자동으로 어서트하므로, 필요하면 개방 직후 `ser.dtr = False`와 `ser.rts = False`로 내립니다.

## 11. 로직 애널라이저 설정

| 항목 | 권장값 | 근거 |
|---|---|---|
| 샘플링 속도 | 최소 2 MS/s, 권장 8 MS/s | 115200 기준 1비트 8.68 μs를 충분히 오버샘플링 |
| 채널 수 | 최소 2, 권장 8 | TXD와 RXD 동시 관찰, I2C 확인 시 SDA와 SCL 추가 |
| 캡처 길이 | 10초 이상 | 주기적 상태 메시지 다회 포착 |
| 트리거 | 하강 에지 | 시작 비트 포착 |
| 프로브 지점 | 트랜시버의 TTL 측 | RS-232 측은 음전압이라 대부분의 저가 애널라이저 입력 범위를 벗어남 |

중요합니다. 저가 로직 애널라이저 입력은 대체로 0 V에서 5.5 V 범위만 허용합니다. SP3232EE의 7번, 8번, 13번, 14번 핀은 음전압이 실리므로 직접 물리면 애널라이저가 손상될 수 있습니다. 반드시 TTL 측인 9번, 10번, 11번, 12번 핀에서 관찰하십시오.
